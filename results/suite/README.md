## Result — the equivalence mode is not a free parameter, and the right choice is per family

`EQUIV=constraint` keys the bank by *which subset of constraints* a program satisfies,
keeping the smallest program per subset. Its pruning power depends on something easy to
miss: **whether a constant can occupy a subset cell.**

- In `max_N` it cannot. No constant satisfies `(>= y x_i)` for all inputs, so cells are
  earned by composites and the bank fills with usable building blocks. This is why the
  earlier `results/max_n_climbs/` runs reached max10 in this mode.
- In `array_search_N` it can. The literal `i` satisfies branch constraint `i+1` by
  itself, so every cell is filled by a size-1 constant. `select_seeds` only promotes
  blocks of size > 1, so no composite seed is ever formed, and rounds 2+ re-enumerate
  the same 130 candidates with 100 % dropped as equivalent. **array_search_2 — the
  smallest problem in the family — is unsolvable in this mode**, while `observational`
  and `both` solve it in 12.6 s.
- `piecewise_N` is the same: each bracket's output constant satisfies that bracket's
  constraint alone.

So constraint-subset equivalence is a *predicate abstraction whose granularity must
exceed what a constant can achieve*. Where it does, it is the strongest mode available;
where it does not, it is degenerate. Reporting one mode across a suite would have
confounded this with problem difficulty.
